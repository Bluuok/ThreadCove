# 搜索与子任务编排

Pi 后端默认注册 `web_search`、`web_fetch` 和 `delegate_research`。主模型与子任务均沿用当前会话的 API 上游与模型，例如 OpenCode Go 的 `deepseek-v4.1-flash`，不运行本地模型。

用户可以直接提出研究问题；需要多条独立研究线时，可以说“分别调查这两个问题，再综合结论”。是否调用工具由模型决定，工具执行、并发和取消由 ThreadCove 宿主负责。

## 搜索和网页读取

- `web_search` 调用 Exa 公开 MCP `https://mcp.exa.ai/mcp`，不携带 Go 密钥，也不需要额外搜索密钥。本次真实请求成功；匿名服务可能限流或变更，429 会明确报错，不自动切换付费服务。
- `web_fetch` 读取公开 HTTP(S) HTML、纯文本或 JSON。只允许标准端口；拒绝本机、内网、保留 IP 和混合公私 DNS 结果；连接固定使用验证过的 IP，每次重定向重新校验。
- 单次网络操作最多 25 秒，网页最多 2 MB，提取文字最多 16,000 字符。压缩响应、PDF、需登录页面及依赖 JavaScript 渲染的页面不属于当前读取范围。
- 网页内容及子报告作为不可信资料传给模型。搜索命中不等于已经阅读全文，最终引用仍应对应实际返回的来源。

这条链路使用模型工具调用，不依赖 OpenCode Go 转发服务端搜索功能。官方 DeepSeek Responses API 的服务端搜索是另一种接入方案，需要对应服务的凭据；当前没有启用。

## 子任务与预算

每次可委派 1–3 个任务，同一个应用 runtime 内所有父会话合计最多运行 3 个子任务，超出时排队。每个父研究回合最多创建 6 个子任务，父子合计最多执行 24 次搜索/读取工具调用。

每个子任务有独立 Pi 会话和工作目录，仅注册搜索与读取工具，宿主也拒绝递归委派。子任务最多 90 秒（含排队），最多 6 次模型请求，每次最多 2,048 输出 tokens；父研究最多 180 秒、12 次模型请求，每次最多 8,192 输出 tokens。SDK 重试及 HTTP 重定向不等于新的宿主工具调用，因此这些上限不是精确的账单金额限制。

父任务停止会取消网络请求并清理运行中和排队的子任务。一个子任务失败时，其他子任务仍可返回结果；保存失败也会等待所有兄弟任务清理完毕。独立启动的多个应用进程各有自己的并发上限。

## 来源与恢复

当前会话 `sessions/<id>/data/` 保存：

- `research-search-*.json`：搜索词、时间、提供方、来源 URL 和搜索文本。
- `research-page-*.json`：最终页面 URL、时间、标题和提取文本。
- `research-agent-*.json`：子任务问题、状态、报告、来源和时间。
- `agent-*/`：每个子任务独立的工作目录。

现有“资料与执行”面板可查看 JSON 产物，父对话保存工具结果和汇总。重启后遗留的 queued/running 子记录会标为 interrupted；不会自动重跑或恢复子任务的 SDK 内存上下文。
